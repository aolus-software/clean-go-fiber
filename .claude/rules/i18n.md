# Rule: Messages (no i18n)

The Go target has **no i18n catalogue**. User-facing messages are English only. This differs from
the sibling TypeScript repos (`en`/`id` catalogues) and is deliberate until the owner asks for
localisation.

## Where strings live

- Client-facing messages are set where the error or success is produced: `*errors.AppError`
  constructors called from services, and the success message passed to the response helper by the
  handler. Field messages from validation come from `internal/libs/validator`.
- Keep wording consistent across modules: `"<Entity> not found"`, `"<Field> already exists"`,
  `"<Entity> created successfully"`.
- Mail subjects and bodies are built in the service that enqueues the task.

## Don't

- Don't format internal error text into a client message.
- Don't introduce a localisation library without an owner decision — it is a new dependency.
