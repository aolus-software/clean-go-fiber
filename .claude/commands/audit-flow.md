# Audit Flow

Run a structured, **read-only** audit of this backend and record the results in
`docs/audit-findings.md`. This command **never changes application code, migrations, seeds, or
config** — its only output is the findings document.

`$ARGUMENTS` (optional) narrows scope to specific categories or paths (e.g. `audit-flow auth rbac`,
`audit-flow internal/modules/users`). **With no arguments, sweep the entire codebase** as defined
under "What a full sweep covers".

## How to run it

1. **Read the ground truth first**: `CLAUDE.md`, every `.claude/rules/*.md`, and
   `.claude/rules/audit-findings.md` in particular — that is the writing contract. A finding is
   always "code vs stated intent", never "code vs the auditor's taste". Where no rule states an
   intent, say so in the finding rather than inventing one.
2. **Build the inventory before dispatching anything**: every folder under `internal/modules/`, every
   package under `internal/libs/`, every repository in `internal/repositories/`, every model in
   `internal/models/`, every migration pair in `internal/database/postgres/migrations/`, every task in
   `internal/queue/tasks/` and its handler in `internal/worker/handlers/`. Keep this list — the
   Coverage section is written from it.
3. **Dispatch parallel read-only `Explore` subagents** — one per category below, each given its slice
   of the inventory so every file has an owner.
4. **Each subagent returns evidence, not prose**: `file:line` for every claim, the intended behaviour
   per the rules, what the code does, the gap, and **CONFIRMED** (traced end to end) or **SUSPECT**
   (plus what would settle it).
5. **Write the findings up yourself, in the main thread**, each with the five blocks of
   `.claude/rules/audit-findings.md`: **Where** · **What this is** · **Why this can happen** ·
   **What it costs** · **What we should do**. Tag each 🔴 bug · 🟠 inconsistency · 🟡 hygiene · 📄 doc,
   by consequence.
6. **Write the Coverage section** — what was reached, and what was deliberately not.
7. **Write "Top priorities" last**, ordered security → data integrity → correctness → hygiene/doc.
8. **Report a short summary to the user. Do not fix anything.**

## What a full sweep covers

| Area | Includes |
|---|---|
| `cmd/server`, `cmd/worker`, `cmd/seed`, `cmd/migrate` | boot order, the global middleware chain, error handler, migrations on boot, graceful shutdown |
| `internal/bootstrap/` | constructor wiring of repositories, services, handlers |
| `internal/modules/auth/**` | login, refresh, register, verify-email, resend, forgot/reset password |
| `internal/modules/{users,roles,permissions,selectoptions}/**` | the settings surface and the RBAC catalogue every guard depends on |
| `internal/modules/{profile,health,docs}/**` | self-service surface and the unauthenticated surface; what each discloses; the `ENABLE_API_DOCS` gate |
| `internal/middleware/`, `internal/guards/` | bearer verification, token `type` check, `UserInformation` cache-aside, `guards.Permission` / `guards.Role` and the `superuser` bypass |
| `internal/repositories/` | soft-delete filtering, sort/filter allow-lists, `WithTx` threading, `(nil, nil)` for not found |
| `internal/models/`, `internal/database/postgres/**` | models vs migrations, seed idempotency |
| `internal/libs/**` | cache keys and TTLs, pagination parser, validator, response helpers, token and hash utilities, mailer |
| `internal/queue/**`, `internal/worker/**` | task payloads, `MaxRetry`, error returned for retry, failure logging |
| `internal/config/` | every env var read, required vs defaulted |
| repo root | `Makefile`, `.env.example`, `Dockerfile`, `docker-compose.yml`, `.github/workflows/ci.yml` |

**Deliberately out of scope** (state this in Coverage): `tmp/`, `docs/docs.go` / `docs/swagger.*`
(generated by swag), `go.sum`, and `.agents/skills/` (vendored; `.claude/skills` links to it).

## Categories to cover

1. **Auth & token flows** — register → verify-email → login, forgot → reset; tokens hashed at rest,
   single use via `used_at`, expiry checked, revoke-on-issue; refresh tokens rejected as access tokens
   and vice versa; status and soft-delete enforced at login, refresh, and in `middleware.Auth`.
2. **Access control** — every route under `/settings` against its guard; a permission string no
   seeded permission matches (fails closed for everyone but `superuser`); the superuser role's
   protection from rename/delete; any route acting on another user's id without a check.
3. **Ownership & self-service** — `/profile` and every `:id` route. A privilege-escalation path is 🔴
   and sorts first.
4. **Soft delete & data integrity** — every read on `users` filtering `deleted_at IS NULL` (GORM's
   `gorm.DeletedAt` scope, or an explicit clause in raw SQL); `Unscoped()` usage; multi-write
   operations inside a service-owned transaction; the partial unique email index.
5. **Secrets & sensitive data** — password hashes, JWT secrets, raw tokens absent from logs,
   responses, swag examples, and queue payloads other than the mail body; env read only in
   `internal/config/`.
6. **Response-contract completeness** — handlers that bypass `utils` response helpers; an error path
   that leaks `err.Error()`; swag annotations missing a status the handler can return.
7. **Dead code, unused fields & validation** — request fields the service never reads; validator tags
   that disagree with the contract; allow-lists that drifted from the schema.
8. **Caching & queues** — a cached `UserInformation` not invalidated when status, roles, or role
   permissions change (a **security** finding); enqueue errors swallowed; mail sent inside a
   transaction.
9. **Data model & migrations** — models vs SQL, an edited already-applied migration, indexes missing
   on filtered or sorted columns.
10. **Documentation drift** — `CLAUDE.md`, `README.md`, `docs/*.md`, `.claude/rules/*` vs the code:
    env names, routes, permission strings, `Makefile` targets.

## Rules for this command

- **Read-only.** Report, do not act (`.claude/rules/contradiction-halt.md`).
- **Prefer updating the existing `docs/audit-findings.md`** — never renumber a finding; append.
- **Cite `file:line` for every finding.**
- **There are no `_test.go` files yet.** Do not report test results; an unguarded invariant with no
  test is a finding in its own right.
